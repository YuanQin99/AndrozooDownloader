# AndroZoo CSV Filter and APK Downloader

English | [中文](README_CN.md)

This project provides three independent tasks:

1. Filter an AndroZoo `latest.csv` by the year in `vt_scan_date` and the `vt_detection` count.
2. Scan once and split yearly benign and malware samples into separate CSV files.
3. Read SHA-256 values from the filtered CSV, download APKs with multiple processes, and record every result.

## Installation

```powershell
python -m pip install -r requirements.txt
```

Edit the included `config.json` before running the scripts. `config.example.json` is a clean example that can
be used to restore the configuration:

```powershell
Copy-Item config.example.json config.json
```

## Configuration

```json
{
  "filter": {
    "input_csv": "data/latest.csv",
    "output_csv": "",
    "year": 2024,
    "min_vt_detection": 6,
    "max_vt_detection": null
  },
  "yearly_filter": {
    "input_csv": "data/latest.csv",
    "output_dir": "filtered/yearly_2018_2025",
    "start_year": 2018,
    "end_year": 2025,
    "benign_vt_detection": 0,
    "malware_min_vt_detection": 5
  },
  "download": {
    "input_csv": "",
    "download_dir": "downloads/apks",
    "result_csv": "downloads/download_results.csv",
    "workers": 4,
    "max_downloads": 0,
    "random_seed": 42,
    "resume": true,
    "api_key": "YOUR ANDROZOO API KEY",
    "timeout_seconds": 120,
    "retries": 2,
    "chunk_size": 1048576,
    "proxy": {
      "enabled": false,
      "url": "http://127.0.0.1:7897"
    }
  }
}
```

The example uses paths relative to the project directory:

- `data/latest.csv` means `<project>/data/latest.csv`.
- `downloads/apks` means `<project>/downloads/apks`.
- `downloads/download_results.csv` means `<project>/downloads/download_results.csv`.

Absolute paths are also supported. Backslashes in a Windows path must be escaped in JSON, for example
`D:\\data\\latest.csv`. Forward slashes such as `D:/data/latest.csv` also work.

### `filter` settings

| Field | Required | Description |
| --- | --- | --- |
| `input_csv` | Yes | Path to the latest AndroZoo `latest.csv`. It must contain `vt_scan_date` and `vt_detection`. |
| `output_csv` | No | Filtered CSV path. An empty string generates a condition-based filename in the project directory. |
| `year` | Yes | Target year read from `vt_scan_date`, such as `2024`. The filter does not use `dex_date`. |
| `min_vt_detection` | Yes | Inclusive lower bound for `vt_detection`. |
| `max_vt_detection` | No | Inclusive upper bound for `vt_detection`; `null` means no upper bound. |

All configured conditions must match:

```text
year of vt_scan_date == year
and vt_detection >= min_vt_detection
and vt_detection <= max_vt_detection (when max is not null)
```

For example, `year=2024`, `min=6`, and `max=null` generates:

```text
filtered_vt_scan_2024_detection_ge_6.csv
```

To select records where `vt_detection` is exactly 6, set both bounds to 6:

```json
"min_vt_detection": 6,
"max_vt_detection": 6
```

Rows with an invalid date or detection count are skipped and included in the final invalid-row statistics.
The filter displays percentage, throughput, ETA, processed rows, and matched rows using `tqdm`.

### Why time is filtered with `vt_scan_date`

This project follows the dataset construction rationale described in the TIF paper. The selected year is an
approximation of when an APK was observed by a security-analysis platform; it is not the APK's actual build year
or app-store release year.

TIF studies distribution drift caused by malware evolution. Its data must therefore preserve a realistic temporal
order: past observations are used for training and later observations are used for testing. The paper calls this
timestamp the **application observation date** and uses it to construct temporal environments.

The other AndroZoo date fields are not used for the following reasons:

- `dex_date` is the timestamp attached to `classes.dex` inside the APK. It can be modified or generated by build
  tools. AndroZoo explicitly warns that it is often unreliable and that many APKs have a 1980 date.
- `added` is the date on which the APK was added to AndroZoo. An APK may have existed for years before being
  collected, so this is not necessarily its first-seen or release date.
- VirusTotal's `first submission date` is a better representation of when a security platform first observed the
  sample, but querying it individually for an entire dataset is restricted by API access limits.

The TIF authors queried VirusTotal's `first submission date` for 10% of newer samples and compared it with
AndroZoo's `vt_scan_date`. The dates were closely aligned, so the authors used `vt_scan_date` as a scalable proxy
for the application observation date across the full dataset. See
[Appendix A.2: Timestamp selection](https://arxiv.org/html/2502.05098v1) and the
[official AndroZoo field documentation](https://androzoo.uni.lu/api_doc).

Consequently, this configuration:

```json
"year": 2024
```

selects APKs whose `vt_scan_date` is in 2024—approximately samples observed or scanned by VirusTotal in 2024.
It does not claim that those APKs were built or released in 2024.

The paper also labels samples with `vt_detection > 4` as malware. To reproduce that threshold exactly, use:

```json
"min_vt_detection": 5,
"max_vt_detection": null
```

The example value `min_vt_detection=6` is a stricter filter and is not the paper's original threshold.

### `yearly_filter` settings

| Field | Required | Description |
| --- | --- | --- |
| `input_csv` | Yes | Path to the AndroZoo `latest.csv`. |
| `output_dir` | Yes | Directory for yearly class CSV files and the count summary. |
| `start_year` | Yes | Inclusive first year. |
| `end_year` | Yes | Inclusive last year. |
| `benign_vt_detection` | Yes | Exact `vt_detection` value for benign samples; configured as 0. |
| `malware_min_vt_detection` | Yes | Inclusive malware threshold; 5 implements the paper's `vt_detection > 4` condition. |

Run:

```powershell
python filter_yearly.py --config config.json
```

The default configuration scans `latest.csv` once and splits samples from 2018 through 2025 by `vt_scan_date`.
It creates two files per year:

```text
filtered/yearly_2018_2025/
├── benign_2018_vt_detection_eq_0.csv
├── malware_2018_vt_detection_gt_4.csv
├── ...
├── benign_2025_vt_detection_eq_0.csv
├── malware_2025_vt_detection_gt_4.csv
└── yearly_counts.csv
```

Classification rules:

- Benign: `vt_detection == 0`.
- Malware: `vt_detection >= 5`, equivalent to `vt_detection > 4`.
- Samples with `vt_detection` from 1 through 4 are excluded from both classes.
- Samples outside 2018–2025 are excluded.
- Each output preserves the original header and all columns. A header-only file is still created when a year has no matches.
- `yearly_counts.csv` records yearly benign, malware, and total selected counts.

Paths and years can be overridden temporarily:

```powershell
python filter_yearly.py --config config.json --start-year 2020 --end-year 2024
python filter_yearly.py --config config.json --input data/latest.csv --output-dir filtered/custom
```

### `download` settings

| Field | Required | Description |
| --- | --- | --- |
| `input_csv` | No | CSV containing `sha256`. When empty, the filter output path is selected automatically. |
| `download_dir` | Yes | APK destination directory. It is created automatically. Files are named `<sha256>.apk`. |
| `result_csv` | Yes | Path to the download result CSV. |
| `workers` | Yes | Number of parallel download processes. Minimum: 1. Start with 4 and adjust as needed. |
| `max_downloads` | No | Maximum APKs to download in this run. `0` or `null` means unlimited; a positive integer sets the limit. |
| `random_seed` | No | Random-sampling seed. The same input, successful-result history, and seed select the same SHA-256 values. |
| `resume` | Yes | `true` skips SHA-256 values already recorded with `success=1`; `false` reruns all entries and replaces the result log. |
| `api_key` | Yes | AndroZoo API key. The downloader exits when this is empty. |
| `timeout_seconds` | No | Per-request read timeout in seconds. Default: 120. |
| `retries` | No | Retries after failure. A value of 2 allows up to 3 total attempts including the initial request. |
| `chunk_size` | No | Streaming write chunk size in bytes. `1048576` equals 1 MiB. |
| `proxy.enabled` | Yes | `true` uses the proxy; `false` connects directly. |
| `proxy.url` | When enabled | Proxy URL including its scheme, for example `http://127.0.0.1:7897`. |

The download limit is applied after successful history, duplicate values, and invalid SHA-256 values are excluded.
For example:

```json
"max_downloads": 100,
"random_seed": 42
```

- When no more than 100 eligible candidates remain, all of them are downloaded.
- When more than 100 remain, 100 are selected uniformly at random.
- With `resume=true`, previously successful APKs do not consume the current run's 100 slots.
- Reservoir sampling bounds memory use instead of loading the entire large CSV for random selection.
- Set `random_seed` to `null` if a different sample on each run is preferred.

## Filter the CSV

```powershell
python read_csv.py --config config.json
```

Command-line options can temporarily override the configuration:

```powershell
python read_csv.py --config config.json --year 2023 --min-detection 5 --max-detection 20
```

The output preserves the original header and all columns while filtering the data rows.

## Download APKs with multiple processes

Set `download.api_key` in `config.json`, then run:

```powershell
python apk_download.py --config config.json
```

The worker count, destination, and proxy can be overridden from the command line:

```powershell
python apk_download.py --config config.json --workers 8 --download-dir downloads/apks
python apk_download.py --config config.json --proxy http://127.0.0.1:7897
python apk_download.py --config config.json --no-proxy
```

The result CSV contains the SHA-256, absolute file path, `success` flag, status, HTTP status, file size,
error details, and UTC completion time. `success=1` means success; `success=0` means failure.

Common status values:

- `downloaded`: downloaded successfully in this run.
- `already_exists`: a non-empty APK already exists and is treated as successful.
- `failed`: request or filesystem failure; see `error` for details.
- `invalid_sha256`: the value is not a 64-character hexadecimal SHA-256.
- `worker_error`: an unexpected worker-process failure.

Each download is first written to a `.part` file and renamed to `.apk` only after completion. Failed
downloads do not leave incomplete APK files behind.
